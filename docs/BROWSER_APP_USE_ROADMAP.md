# 浏览器与 App 使用能力迭代方案

目标：用户给出一项任务后，Agent 能跨搜索、网页和已连接的 App 收集事实、完成必要操作、核对结果，并交付可复查的产物。浏览器是覆盖面最广的 App 适配器，但任务状态、证据和执行记录应独立于浏览器实现。

## 样例验收任务

“为情侣制定后天出发的伦敦 7 天旅行方案，包括每日行程、机票预算、穿搭建议和酒店选择。”

系统应把“后天”按用户时区转成绝对日期，搜索目的地和官方开放信息，在真实网页上核验日期相关的航班与酒店报价，并交付一份含来源链接、查询时间和预算区间的 7 天计划。出发城市、预算或旅客信息缺失时，先根据已知上下文推断；无法推断时给出明确假设和可替换选项，继续完成可用版本。预订动作要以网站实际确认页和订单号为完成依据；仅打开预订页不能写成“已预订”。

## 当前差距

| 环节 | 当前能力 | 主要缺口 |
| --- | --- | --- |
| 任务识别 | 通用工具路由；旅行请求现已选中搜索与浏览器工具 | 缺少旅行专用的日期、人数、预算、出发地和偏好结构化提取 |
| 搜索 | 豆包搜索可返回来源与摘要；`fetch_url` 可读取公开页面 | 缺少多查询研究计划、同一事实的交叉核验和引用快照 |
| 浏览器 | WebBridge 支持真实登录态、导航、快照、填写、点击；现可提取页面文本与链接、滚动长页 | 缺少带完成条件的多步行动循环、页面变化恢复、反自动化页面处理、价格字段抽取与持久化的浏览器任务状态 |
| 行程 | Agent 可写报告和目标文稿 | 缺少日程、地理距离、开放时间、天气与预算之间的结构化校验 |
| 机票与酒店 | 可进入供应商网页查看 | 缺少同日期、人数、币种、行李/税费、取消政策的标准化报价与复查机制 |
| 交付 | 文件、文稿和工具记录可持久化 | 缺少“已核验报价 / 估算 / 未确认”标注、来源时间戳与用户可继续操作的供应商链接 |

## 迭代顺序

### 1. 可靠研究与报价证据

- 建立 `TripBrief`：日期与时区、出发地、人数、预算、偏好、证件和住宿条件。相对日期在任务开始时固定，避免长任务跨天漂移。
- 把搜索拆成目的地攻略、交通、航班、住宿、天气和开放时间等独立查询。优先从官方景点、交通和预订供应商页面核验关键事实。
- 建立 `QuoteEvidence`：供应商、URL、查询时间、出发/返回日期、人数、币种、含税总价、行李或取消条件、可用状态。缺少字段时明确留空。
- 交付 `TripPlan`：每天上午/下午/晚上安排、跨点交通时间、费用估计、雨天替代、穿搭建议与逐项来源。

### 2. 浏览器行动循环

- 统一 `observe → choose → act → verify` 循环。每一步保留会话、标签页、URL、元素标识、动作、结果和截图或文本证据；页变后重新观察，不盲点旧元素。
- 扩展 WebBridge 适配器：搜索与切换标签页、长页滚动、语义快照、可读内容及链接提取、填写/点击、必要时截图。通用模型只处理任务意图和少量关键决策。
- 为每个子任务设置完成断言，如“酒店列表显示所选入住/离店日期及 2 人价格”，失败后可重试或换供应商；始终区分“浏览成功”和“预订成功”。
- 对登录、验证码、跨域 iframe、支付和网站拒绝合成事件等边界输出可继续执行的位置与所需信息。

### 3. App 使用抽象

- 把浏览器、日历、邮件、地图、机票/酒店平台统一成带 `observe`、`act`、`verify` 和 `evidence` 的适配器。能用稳定 API 的信息优先用 API，必须依赖登录态和页面流程时用浏览器。
- 任务层维护统一状态与幂等键，避免服务重启后重复提交预订或表单。最终动作以提供方确认信息为准。
- 在前端显示研究来源、报价有效时间、当前浏览器步骤、失败原因和可恢复入口。

### 4. 评估 Jev

Jev 可作为浏览器循环中的**局部动作选择器**：给它当前页面可操作元素和允许动作，让它选下一步；WebBridge 继续负责真实浏览器连接，主模型继续负责跨站计划、事实核验和旅行方案。现有 Jev Ultrafast 示例使用自己的 Browser Harness；接入本项目需要另做 WebBridge 状态适配，不能直接替换工具。先用不少于 20 个重复场景比较成功率、每步耗时、费用、页面变化恢复与误操作，再决定是否接入。其公开机票演示只验证出现航班选项，并没有完成订票。

## 首批验收标准

1. “后天出发伦敦 7 天”无需用户说“搜索”或“浏览器”，也能自动调用搜索与浏览器。
2. 输出 7 天行程、至少两种航班预算方案、至少三种酒店选择、天气相关穿搭、总预算和来源链接；价格标明采集时间与估算/实时报价状态。
3. 浏览器每次点击或填写后核对页面状态；站点改版或加载失败时能重试或切换来源，不能把失败操作写成完成。
4. 缺少出发城市或预算时仍交付有假设的可用方案；缺少旅客、支付或网站认证信息时准确停在预订前或失败位置。
5. 服务中断后可看见最后已确认步骤，并避免重复提交可能已产生副作用的动作。
